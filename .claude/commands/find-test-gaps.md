---
description: AI сравнивает SUT с существующими тестами и заводит Jira-тикет на непокрытое
argument-hint: базовый URL приложения (например https://demoqa.com)
---

Найди gap'ы в тестовом покрытии для приложения $ARGUMENTS и заведи задачу в Jira.

Действуй как QA, который только что присоединился к команде и хочет понять, где
самые опасные дыры в покрытии. Цель — НЕ покрыть всё, а найти **одну** самую
очевидную и важную непокрытую функциональность и завести на неё тикет.

Шаги:

**1. Инвентаризация существующих тестов**
- Прочитай `tests/specs/` — какие .spec.ts файлы есть, какие фичи они покрывают
- Прочитай `tests/pages/` — какие страницы уже есть в Page Object Model
- Кратко перечисли что уже покрыто

**2. Инвентаризация SUT**
- Открой $ARGUMENTS через playwright MCP
- Если это лендинг с навигацией (как demoqa.com) — собери список доступных разделов/страниц
- Для каждого раздела на 1-2 предложения опиши что там за функциональность
- НЕ ходи глубоко везде — поверхностный обзор

**3. Найти gap**
- Сопоставь покрытие с SUT
- Выбери ОДНУ функциональность которая:
  - Видимо не покрыта тестами
  - Достаточно простая чтобы автоматизировать за разумное время
  - Достаточно интересная чтобы продемонстрировать на ней полный QA-флоу (есть состояния, валидация, edge cases)
- Если несколько подходят — выбери самую видную для пользователя

**4. Создать тикет в Jira через atlassian MCP**
- Перед созданием — покажи мне draft и спроси подтверждения
- Структура тикета:
  - **Type:** Task
  - **Summary:** Покрыть тестами {название фичи} на {URL}
  - **Description:**
    ```
    URL: {точный URL страницы}

    Контекст:
    {1-2 предложения почему эта функциональность важна}

    Текущее состояние:
    Не покрыто автотестами. Найдено в ходе аудита {today's date}.

    Acceptance criteria:
    Уточнить из реального поведения сайта в процессе работы над тикетом.

    Definition of Done:
    - [ ] Risk-анализ создан
    - [ ] Тест-кейсы в Gherkin
    - [ ] Автотесты на P0/P1 написаны и зелёные
    - [ ] PR открыт с описанием покрытия
    ```
  - **Priority:** Medium
- После создания — выдай мне ID тикета и ссылку

**5. Финальный отчёт**
Кратко:
- Что уже покрыто (1-2 строки)
- Какие gap'ы нашёл (список)
- На какой завёл тикет и почему именно на эту
- Следующий шаг: «Запусти `/qa-from-jira <TICKET-ID>`»

ВАЖНО: не создавай несколько тикетов за раз. Один прогон — один тикет на самый важный gap. Это демо-команда, цель — показать процесс.

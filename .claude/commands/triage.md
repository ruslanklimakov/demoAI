Проанализируй результаты последнего прогона тестов ($ARGUMENTS).

1. Прочитай `playwright-report/` или `test-results/` — собери все упавшие тесты
2. Для каждого упавшего теста:
   - Прочитай error message и stack trace
   - Посмотри trace.zip / video, если есть
   - Открой соответствующий .spec.ts файл
   - Классифицируй причину падения:
     - `FLAKY` — race condition, неудачный селектор, таймаут (фиксим тест)
     - `BUG` — реальный регресс в продукте (заводим тикет в Jira)
     - `STALE` — устаревший тест, требование изменилось (обновляем тест)
     - `INFRA` — упало окружение / сеть / зависимость (репортим DevOps)
3. Для каждого `BUG` — предложи завести тикет в Jira: title, description, severity, шаги воспроизведения (через atlassian MCP — создай драфт, но НЕ публикуй без подтверждения)
4. Для каждого `FLAKY` — предложи конкретный фикс (заменить селектор, добавить waitFor, etc.)

Отчёт в формате:
| Test | Status | Category | Action |
|------|--------|----------|--------|
| ... | Failed | BUG | Draft Jira: ... |

В конце — рекомендация: можно ли мерджить PR / релизить, или есть блокеры.
